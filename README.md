# 证据台 TRACE｜投资事件情报与证据时间线

第三题（原题编号 08）的可运行 Web 原型。把同一事件拆为可单独核对的主张，保留原始证据、四类时间及每次结论变化。

**当前版本：v1.3。已接入扶摇个股资讯摘要与快讯，支持查询、选取、分析、人工复核、事件归属与时间线跟踪。MiniMax真实分析已验证；iFinD未接入。** 不把规则分析或构造数据展示为 AI/实时金融数据。

## 启动与验证

需要 Node.js 22.9+ 和 npm；本次实际验证环境为 Node.js 23.10.0 / npm 10.9.2。

```bash
# 在解压后的 03_投资事件情报与证据时间线 目录执行
npm ci
npm run dev
```

无需密钥即可操作规则分析、事件归属确认、主张复核、证据时间线和版本变化。默认端口 4303；如果被占用，使用 `PORT=4304 npm run dev`。

```bash
npm test                 # 领域规则与接口契约测试，mock 与真实情况分开记录
npm run build            # 生成可部署的、自包含的 Worker ESM
npm run validate         # 检查构建产物可被作为 ESM 加载
npm run check            # 测试 + 构建 + 产物校验
npm run package:submission # 生成排除密钥/依赖/缓存的干净提交目录
```

`npm ci` 会通过根目录 `postinstall` 安装 `app/` 锁定的 esbuild 构建依赖。应用运行时使用 Web 标准 API 与 Node 内置模块，无其他生产依赖。浏览器需支持 ES Modules、原生 dialog、localStorage 和 crypto.randomUUID（当前 Chrome/Edge/Safari 等现代浏览器）。

## 2 分钟上手

1. 打开默认「海岬储能项目」构造案例，查看投资口径 **10 亿元 / 8 亿元冲突**。
2. 点「录入新材料」→「更正金额，解决冲突」→「规则分析 → 人工核对」。
3. 核对归属事件、主张类型、金额及指向的旧证据，勾选人工复核后提交。
4. 当前金额变为 **8 亿元**，协议签署状态不变；「更新记录」显示前后变化，旧 10 亿元证据仍可打开。
5. 用「历史回放」切到前 4 份材料，重新查看更正前的冲突；刷新验证新增材料仍保留。
6. 切到「临川医疗」看否认和适用期结束；切到「微软」看真实历史监管/交割进展与原始页面。

也可粘贴自己的合法公开材料，手动填写来源与已知时间，选择已有事件或新建事件，并添加独立的核对事项。歧义必须人工确认，不自动写入结论。

## 产品选择与判断规则

- **用户任务**：小范围跟踪公司事件，核对来源与变化；不做全网新闻聚合。
- **判断粒度**：事件 → 主张 → 证据。例如金额更正只替换金额，不覆盖整个事件。
- **分类**：事实陈述、观点、推测、传闻分别标记。「事实陈述」不等于真实已获证明。
- **权重**：原始性、直接性、来源核验与内容类型对应高/中/低规则，页面解释原因；不是概率。用户选择「公告」不会自动获得高权重。
- **冲突**：同范围内有来源记录的事实陈述相反时标记冲突，包含新闻；新闻一致仍待核实，不自动变成直接证据。
- **替换条件**：更新/更正必须指向同主张、同适用范围的旧证据，且权重不低、披露时间不早于目标。否则保留冲突/待核对提示。
- **时间**：发生、披露、抓取、材料更新分别保存，另有系统录入时间；原始日期精度与缺失均保留。页面每10秒重算到期状态，编辑对话框关闭后或返回前台时复核，不产生额外资讯请求。历史回放按录入前缀展示已知证据，有效期仍按今天判断；更新记录按当次录入时间重算。
- **否认与过期**：展示否认范围，不宣判客观真相；适用期结束不推导为历史事实为假。
- **来源追溯**：结论可回到具体主张、逐字摘录及原文链接；转载使用同一来源组，不虚增独立佐证。

详细设计见 [产品与技术说明](./docs/产品与技术说明.md)。

## AI 的角色与配置

开发过程中使用 Codex 辅助阅读、设计、编码、测试与修正，记录见 [AI 使用与验证记录](./docs/AI使用与验证记录.md)。

产品 AI 仅提取原文片段、建议信息类型及事件归属。程序负责校验、去重、版本与状态计算，人工确认后才保存。AI 模式采用真实接口响应，不用预置案例答案替代模型输出。

线上已按用户要求从普通 `wym` 密钥更换为个人 M Plan 订阅 Key，通过 Sites 服务端 Secret 配置 MiniMax。密钥值没有写入本地文件、源码、前端、日志或提交包。当前设置：

```dotenv
MODEL_BASE_URL=https://api.minimax.cn/v1
MODEL_NAME=MiniMax-M3.1-Flash
MODEL_API_KEY=仅在服务端秘密变量中设置
FUYAO_API_KEY=仅在服务端秘密变量中设置
```

如需本地联调，参照 [app/.env.example](./app/.env.example) 自行创建未跟踪的 `app/.env`，不要把真实值提交。提交包默认不带密钥，因此本地 AI 未配置时仍返回503，规则分析可用。

MiniMax 使用其 OpenAI 兼容端点，但采用专用适配：低档思考、思考与正文拆分、4,096输出token上限、45秒超时，不假设供应商支持通用的JSON模式参数。程序只接受可定位的引用与合法JSON；截断、业务错误、余额不足不会保存为正常结论。[官方说明](https://platform.minimax.cn/docs/api-reference/text-chat-openai)。

旧普通密钥曾返回 `HTTP 402: insufficient balance (1008)`；更换订阅 Key 后，已通过公开网站完成一次真实模型分析与人工复核保存，刷新后原文引用仍可追溯。模型建议的归属与金额字段仍需人工修正，单次成功不代表准确率。证据见 [MiniMax 配置与联调](./docs/MiniMax配置与联调.md)。

已加入每个运行实例内的限流：每访问来源每分钟3次/每天30次，实例合计每天100次、并发2次。计数在实例重启或跨实例时不共享，是尽力保护，不是持久化的全局账单上限；未实现账号鉴权或供应商侧硬支出封顶。

## 数据与存储边界

- 默认 3 起事件、11 份材料：1 起真实历史事件（4 个原始页面的必要摘录）和 2 起虚构事件（7 份构造材料）。
- 真实资料截至 **2023-10-13**，本次页面核对日期 **2026-10-30**；不是今天的市场信息，也不代表完整事件资料库。
- 扶摇个股新闻与快讯公开查询接口已真实验证；来源、抓取/披露/更新时间与原链接保留。iFinD未接入；不代表已获得无限再分发数据许可。详见[扶摇接入与验证](./docs/扶摇接入与验证.md)。
- 只收录公开原始页面的必要摘录与链接，不保存研报全文或受限金融数据。具体出处见 [数据来源与样例说明](./docs/数据来源与样例说明.md)。
- 工作区保存在当前浏览器的 localStorage。不同浏览器配置/设备互不共享；同一配置中的多个标签页共用存储，未实现并发合并。跨设备使用导出/导入 JSON。清除浏览器数据会丢失新增记录。
- 查询扶摇时向服务端发送栏目或A股代码；仅点击AI分析才发送材料原文给模型。没有全文爬虫、自动订阅、推送、真实持仓或多用户数据库。
- 产品不输出确定性涨跌预测、收益承诺或直接买卖建议。外部原文作为引用呈现，并与核实结论分开。
