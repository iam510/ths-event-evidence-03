# 产品与技术说明

版本 v1.3，2026-10-31。对应代码均在 `app/` 内。原实施规划保留作为决策记录，以下描述实际实现。

## 核心设计

用户面对的是「这一条消息改变了什么」而不是「再给我一段新闻摘要」。产品以主张为判断单位：协议签署、项目金额和业绩判断互不覆盖。同一材料可含多条不同类型的主张。

事件工作台提供公司/关键词搜索、冲突与待核实筛选、证据时间线、主张与冲突页、更新记录，以及来源清单。每条证据可展开来源、必要原文摘录、逐字引用、四类时间、来源组、信息类型、权重与指向的旧版本。标的关系包含内置核对记录和用户在材料复核页填写的关系；新增关系必须有逐字原文依据并指向本份材料，支持同名更新。没有核对过的关系时明确显示缺失。

录入分两步：先填写材料与元信息，再分析并复核归属和主张。规则结果或 AI 建议都必须经过用户勾选确认。支持另建事件和添加核对事项；不对不确定的事件匹配自动写入。更正、更新必须明确选择旧证据。

## 实际技术选择

采用原生 JavaScript ESM、HTML、CSS 和 Web 标准 Request/Response/fetch，无前端框架与生产包依赖。原因是本题交互以证据核对和状态变更为主，减少安装与运行依赖，方便在提交包内复现。规划中的 TypeScript 未采用，这是首版的取舍；结构约束通过运行时校验与测试实现。

esbuild 为唯一构建依赖，将 Worker 及页面、样例等资产打包成自包含 ESM。部署产物位于根目录 `dist/server/index.js`，本地开发服务器按同一路由提供原始页面与接口。

- `src/core.js`：浏览器与服务端共用的纯规则；主张状态由证据重算。
- `src/app.js`：DOM 界面、材料复核、事件归属确认、localStorage、导入导出。
- `src/api.js`：受控的模型端点、结构和逐字引用校验。
- `worker/index.js`：托管路由与安全响应头。
- `scripts/server.mjs`：本地 Node HTTP 入口。

未采用服务器文件存储，避免无服务器环境临时文件丢失问题。首版明示使用浏览器存储和 JSON 备份，未实现跨设备实时同步与多标签并发合并。

## 数据模型与规则

事件包含主体、对象、类型、主张定义、材料和标的关系。材料包含正文、来源、来源类型/核验标记、来源组、真实/构造标记和四类时间。每条证据陈述包含主张 ID、逐字引用、类型、主张值、单位、范围、支持/否认/更正/更新关系、目标证据和可选有效期。

主张状态是有直接依据、存在否认、证据冲突、待核实或适用期已结束。事件状态汇总主张，不输出涨跌方向。

证据权重规则：观点、推测、传闻为低；真实材料无来源链接为低；内置经过人工核对的公司/监管原始披露为高；用户录入有链接但未经独立核验的材料最高为中。内置构造情境中的原始公告可为高，但始终显示构造标记，不能解释为真实核验。

同主张同范围下，仍有效、有可核对来源的事实陈述（包括新闻）值/单位不一致，或支持与否认并存，标为冲突；不按来源数量投票。不同范围分开判断，页面证据中展示范围。首版未实现同义句对齐、单位/币种换算或完整事实图谱，因此语义等价但字面不同的值可能产生保守冲突，需人工统一主张口径。

更新/更正覆盖条件：目标存在且属于同主张、范围一致、内容为事实陈述、权重不低于目标、披露/更新时间不早于目标。时间未知则不自动覆盖。旧证据不删除。普通较晚的新陈述不会仅因时间晚而自动压过旧陈述。

精确重复原文（忽略空白、全半角和英文大小写）拒绝入库；标点和小数点保留，避免把 1.0 误当 10。转载通过来源组链接，独立计数按来源组去重；用户未识别的转载不能保证自动发现。

## 时间语义

发生时间可早于或晚于披露时间，未知可为空。披露时间、材料更新时间来源于材料；系统生成录入时间；扶摇成功取数时另记录抓取时间capturedAt，缓存保留该时点，旧材料没有抓取记录时显示缺失。材料更新时间不得早于披露时间。完整时间须带时区，日期精度单独保留；界面统一显示 UTC+8，不补造未知时间。

时间线支持按披露、发生和录入排序。历史回放按已录入材料的前缀展示，提示有效期仍以今天判断；「更新记录」按该次录入的时间生成前后对比。导入时依据真实材料重算记录，拒绝直接相信 JSON 中的历史摘要。

仅日期的有效期按界面所示北京时间当日23:59:59结束，带时区时间则按其精确时刻处理；这不改变原始披露日期的精度。过期针对显式提供的有效期；缺少有效期不臆测事件到期。资料新鲜度按最新披露/材料更新时间超过 30 日标记陈旧，仅为首版提醒规则，不是金融业务统一标准。抓取/录入旧消息不会让它重新变新。

## AI 与失败边界

产品 AI 端点仅在明确点击后调用已配置的兼容模型，45 秒超时，限制输入 12,000 字符、候选事件 50 个、输出主张 8 条。模型不能决定来源权重和最终状态。

模型自由生成的 `value` 不采用；以经过原文逐字校验的引用作为待核对值，避免凭空给出金额。目标证据和具体主张字段仍由用户复核。结构、事件 ID 或引用不合法时拦截；无配置返回 503，上游失败返回 502，超时返回 504。界面保留输入及旧结论。

当前已适配MiniMax并配置服务端Secret。旧普通密钥曾返回HTTP402余额不足；更换M Plan订阅Key后，已完成一次真实分析、人工复核、保存、刷新与引用追溯。模型归属与金额规范化仍需人工修正，不声称实测准确率。错误、边界与超时另由mock覆盖。已增加每实例内的频率、日计数与并发保护，但不是跨实例共享的硬账单封顶，仍未实现账号访问控制。

## 安全与当前限制

来源正文以转义文本显示，不执行 HTML。链接限 HTTP/HTTPS 且拒绝 URL 内嵌凭证；服务端模型地址由环境配置，材料内的 URL 不会触发服务端抓取。AI 请求校验同源 Origin 和 JSON 类型，密钥不返回前端；异常不回显上游敏感信息。Worker 加入 CSP、nosniff、referrer-policy。

仍未完成：iFinD接入、持续自动更新、全文采集、真正全网首发识别、语义级自动去重/合并、持仓、交易、账号及跨设备数据库。浏览器导入文件由用户自行提供，内容仍按不可信文本显示；本地工作区不是多用户共享事实库。

## MiniMax 适配补充

采用 `MiniMax-M3.1-Flash`，端点 `https://api.minimax.cn/v1/chat/completions`。提示词版本 `extract-v1.1`。供应商请求不携带未经验证支持的response_format/temperature，使用reasoning_split、reasoning_effort=low、max_completion_tokens=4096。只解析正文，不显示或保存推理内容；HTTP200内的业务错误、输出截断、格式或引文不合法均拦截。调用仍须人工复核。

每实例每来源每分钟3次、每天30次，实例总计每天100次、并发2次。计数仅在内存，不跨Worker实例/地区持久化；不能视为金融成本硬上限。
